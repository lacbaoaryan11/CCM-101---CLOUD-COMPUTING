# Mission Reflection

This laboratory activity helped me understand the basic components of cloud infrastructure and how they work together. Among the infrastructure components, I think **compute resources** are one of the most important because they provide the processing power needed to run applications and services. However, compute resources also depend on storage, networking, and the operating system to function properly. Through the KillerCoda Linux environment, I was able to see how these resources are present in an actual server.

I also learned how **Linux supports cloud computing**. Linux provides an operating system that allows cloud engineers to manage servers, applications, storage, networking, and other resources. By using commands such as `uname`, `lscpu`, `free`, `hostname`, `ip addr`, and `df -h`, I was able to investigate the server and understand its available resources.

Another important lesson I learned is the importance of **technical documentation before deploying infrastructure**. Documentation helps engineers record system information, configurations, and design decisions. It also makes it easier for other team members to understand, maintain, and troubleshoot the infrastructure. Proper documentation can help prevent mistakes before a system is deployed.

During this laboratory, I learned new skills such as using Linux commands, identifying cloud infrastructure components, comparing cloud services from AWS, Microsoft Azure, and Google Cloud, creating infrastructure diagrams, and writing technical documentation using Markdown. I also practiced organizing files and screenshots in GitHub.

Overall, this laboratory improved my **GitHub Cloud Computing Portfolio** by adding a complete Laboratory 2 project with reports, screenshots, a cloud architecture diagram, and documentation. It helped me become more familiar with cloud infrastructure and gave me practical experience that I can use in future cloud computing activities.
